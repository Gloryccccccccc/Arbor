# 09 分层记忆与上下文压缩

SDKMorph 采用工作记忆、任务记忆、项目记忆和迁移经验四个逻辑层，共用 SQLite、会话文件和产物目录。目标是让升级任务在长对话、错误修复、上下文压缩和进程重启后仍能依据真实状态继续。本文是设计与验收方案，尚未实现这些能力。

## 概念与作用范围

短期或长期描述生命周期，任务或项目描述作用范围，Trace 是执行记录形式，Skill 是可复用操作方法。四个逻辑层不与这些概念一一对应，也不意味着需要四套数据库或四个 Agent。

| 层级 | 保存内容 | 与常见概念的关系 | 使用与存储 |
| --- | --- | --- | --- |
| 工作记忆 | 当前目标、近期对话、相关代码、错误、检索证据和任务摘要 | 包含对话历史中的相关部分，但不等于完整聊天记录 | 每次调用前按预算构建，完整原始记录另行保留 |
| 任务记忆 | 本次升级的目标、约束、确认事实、失败尝试和待办问题 | 类似任务状态快照与结构化工作笔记；Trace 是证据来源之一 | SQLite 持久化，按 taskId 查询，引用对应事件和产物 |
| 项目记忆 | 仓库架构、SDK 封装位置、测试入口和长期约定 | 按仓库隔离的长期记忆 | 附 repoId 和相关文件指纹，代码变化后重新确认 |
| 迁移经验 | 具体升级案例的条件、操作、结果、限制与证据 | 经验证的案例；归纳审核后可以支持 Skill 编写 | 按 SDK、版本、环境等条件检索，首版人工审核后复用 |

例如，Trace 记录三轮修改与检查的输入输出；任务记忆记录当前补丁、仍失败的调用、已经排除的方案和下一步。项目记忆可以记录“此仓库通过一层异步封装访问 SDK”，迁移经验记录某次异常类型迁移如何在指定环境与检查下通过。

## 事实底座与写入权限

- 实际版本、文件和补丁哈希、命令退出码、测试结果由工具写入；任务阶段由领域状态机推进，模型不能直接标记验证成功。
- 模型可以提出假设、工作笔记和经验候选。事实、假设、用户约束与经验保留不同类型和来源，不因摘要而相互转换。
- 用户明确提出的项目约定可以形成项目记忆；模型从代码推断的约定附带位置与指纹，必要时请求确认。
- 迁移经验关联独立验证报告与适用条件，审核通过后才用于跨任务复用；一例成功不意味着通用规律。
- Skill 表达步骤、前置条件和验证方法，引用支撑案例并维护版本；不允许经验提炼自动改写权限或验收规则。

任务状态是程序维护的事实底座。模型上下文和压缩摘要是用于继续推理的视图，不能反向覆盖权威状态。

## 记忆记录与生命周期

| 建议字段 | 作用 |
| --- | --- |
| id、type、scope | 区分事实、假设、约束与案例，限定任务或项目范围 |
| repoId、taskId、branchId | 避免其他仓库、任务或探索分支的信息被错误混入 |
| sdk、sourceRange、targetRange | 定义版本适用条件，使用符合目标生态的版本解析 |
| content、sourceRefs | 保存内容与用户消息、代码、文档、事件和报告等依据 |
| codeFingerprint、environmentFingerprint | 判断相关代码与执行环境变化是否使记录过期 |
| status、revision、supersedes | 表达候选、已确认、过期与被替代关系，保留修订历史 |

写入路径为工具或用户事实直接入库、模型内容先成为候选、必要审核后确认。读取时先按作用域、版本、环境和状态过滤，再按相关性选择；不能只靠向量相似度召回。新用户约束替代旧约束时保留修订关系；相关文件或环境变化后，旧推断和旧经验需要重新核对。

失败尝试记录当时的输入、补丁、错误摘要与条件，防止在同一条件下重复无效操作。条件变化时允许重新判断，不能把一次失败永久写成禁用规则。

## 每轮上下文构建

1. 读取当前任务修订、目标、用户约束和有效检查点，生成确定性事实摘要。
2. 选择与当前阶段有关的项目记忆、版本文档、迁移 Skill 与经审核的经验，保留来源和适用条件。
3. 加入最近的完整对话、相关代码与最新错误，按证据 ID 去重；完整日志按引用读取。
4. 计算系统提示、工具定义、已选上下文、输出预留与安全余量，确保整体满足当前模型预算。
5. 每轮重新确认补丁与验收关联；不能将旧摘要中的“已通过”沿用到新补丁。

大安装日志、完整测试报告和大量文件内容先落盘，工具先返回关键错误、定位信息和产物引用。按需展开比持续把所有原文塞入上下文更容易控制成本。

## 上下文压缩流程

1. 在工具结束并持久化结果的安全点检查预算，阶段切换时也整理上下文。阈值依据模型窗口、输出预留和受限工具结果预算计算，不固定为某个通用百分比。
2. 保存任务修订、当前补丁与环境指纹、覆盖的事件序号和待执行操作，形成压缩前检查点。
3. 从数据库重建目标、硬约束、当前阶段、产物和验收状态；模型只压缩分析过程、候选原因、失败尝试与未解决问题。
4. 保留最近的完整交互及必要工具调用/结果配对，旧历史替换为摘要与引用；不任意删除一侧消息破坏工具调用结构。
5. 校验摘要结构、必要字段与证据引用。摘要记录 coversThroughEventSeq、taskRevision、patchHash 和原文引用；这些检查不能证明自由文本没有错误，硬事实仍以程序生成内容为准。
6. 压缩期间出现新事件时合并增量；若任务或补丁已变化，重建当前事实视图，必要时放弃旧摘要并有界重试。
7. 压缩失败保留原始历史和检查点；空间不足以安全继续时暂停模型执行并报告原因，不盲目丢弃事实或无限重试。

每次压缩的事实字段重新从状态库生成，关键叙述可通过引用回查原文，避免只对上一版摘要反复摘要产生漂移。压缩改变发送给模型的信息，不删除唯一证据，也不修改任务成功状态。

## 压缩后应保留的信息

- 升级目标：SDK、源版本、目标版本与业务约束。
- 当前快照：任务阶段、代码与环境指纹、当前补丁及知识包版本。
- 验证边界：原版本基线、已验证的具体补丁、仍失败的检查和未覆盖项。
- 继续工作所需：已尝试方案、失败条件、待解决问题、下一步与证据引用。

例如，摘要可以说明“当前为 patch-03，两个调用仍失败；方案 X 在当前环境下失败；下一步确认异常类型变化并重新验证”。它不能把旧 patch-02 的测试通过写成 patch-03 已通过。

## Pi 接入与存储边界

复用 Pi 的会话持久化和压缩机制，使用 session_before_compact 接入领域摘要策略，使用 context 钩子在模型调用前构建相关信息视图，并记录 session_compact 或 session_compact_failed 的结果。接口以锁定的 Pi 版本为准。

Pi 会话管理负责模型历史，SQLite 中的领域状态负责任务事实，二者不互相替代。原始会话、事件与产物保持关联；恢复或切换探索分支后，核对 branchId、代码与产物再继续，不把其他分支的成功结论直接带入当前补丁。

本机开发与实验的数据库、Pi 会话和产物目录显式配置到 E:\项目\SDKMorph\.work；生成数据不进入 Git 提交。凭据由 SecretStorage 管理，不作为记忆内容。

## 实施顺序与验收

第一版优先实现任务记忆、项目记忆、检查点和受控压缩；迁移经验先人工审核后检索复用，暂不自动推广为 Skill。实现主要放在 core 的状态、记忆与上下文模块，不新增独立记忆服务。

评估涵盖强制压缩、用户追加约束、补丁变化、过期项目记忆、错误版本经验、压缩失败和进程重启。对比 Pi 基础策略与领域策略时固定任务、模型、工具和总体预算，计入压缩成本，记录约束遗漏、无效重复尝试、恢复结果与最终迁移结果。
