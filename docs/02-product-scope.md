# 02 产品范围与插件交互

第一版以桌面 VS Code 中的单仓库、单 SDK、指定源版本和目标版本为边界。保留项目内依赖清单与升级任务历史，暂不建设跨组织、多仓库的自动治理平台。SDKMorph 负责同一 SDK 的版本升级，不把跨厂商 SDK 替换混为第一版需求。

## 用户操作流程

- 扫描：读取受支持的依赖声明与锁文件，分别展示声明约束、锁定版本和容器内实际安装版本；无法确认时标注未知。
- 计划：选择目标版本，展示候选不兼容变更、受影响文件和文档证据；静态分析结果允许不完整。
- 执行：为当前代码快照创建独立任务工作区，完成环境准备、原版本基线与目标版本迁移；显示阶段、命令摘要、预算和取消入口。
- 审阅：使用原生 Diff 展示补丁，提供迁移依据与验证报告；无法验证、依赖冲突、超出预算时清楚呈现阻塞原因。
- 接受：用户主动接受补丁或创建升级分支；应用前检查原项目是否相对任务快照发生变化，发现冲突停止并提示。

## 插件界面

| 入口 | 内容 |
| --- | --- |
| 依赖视图 | SDK、声明约束、锁定版本、目标版本、升级任务状态 |
| 影响列表 | 文件与位置、变更条目、证据来源、需要人工判断的问题 |
| 任务视图 | 阶段、进度、执行日志、取消与恢复 |
| 结果视图 | Diff、基线与目标测试、未覆盖项、补丁接受入口 |

优先复用 TreeView、命令、诊断与 Diff；复杂结果展示再使用 Webview。聊天用于补充业务约束，不替代结构化任务入口。

## 明确暂缓

- 浏览器版 VS Code、自动合并与自动发布。
- 同时升级多个存在交互影响的 SDK，以及任意包管理器和任意语言。
- 完全无测试项目的行为等价承诺。
- 跨厂商适配、数据库调优和通用开发助手功能。
