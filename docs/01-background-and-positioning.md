# 01 项目背景与竞品定位

SDKMorph 解决 Python 项目升级 SDK 时，依赖版本变化与业务调用代码变化需要共同处理的问题。目标用户是维护 Python 服务、需要审查升级风险的开发者。项目作为个人 AI 应用工程项目建设；没有真实企业使用经历时，不包装为已上线的企业实习项目。

## 用户任务

用户指定仓库和目标版本，希望知道哪些调用会受影响、修改依据是什么、能否自动迁移、执行后哪些验证通过，以及还有哪些风险需要人工判断。一次升级不仅记录版本号，还应保留代码、环境和验证证据。

## 竞品与研究边界

| 参照对象 | 研究关注点 | 本项目要验证的问题 |
| --- | --- | --- |
| Renovate | 已有依赖识别与自动更新能力 | 升级涉及业务调用变化时，能否在更新依赖后继续完成代码修复与验收 |
| Codemod 等迁移工具 | 已有转换规则、工作流与迁移能力 | 确定性迁移规则与 Agent 反馈修复如何配合，是否比单独使用更有效 |
| 通用编码 Agent | 能够阅读文档、修改代码、执行测试 | 领域知识筛选、结构化任务与独立验收能否在同等预算下改善结果 |

存在直接和间接竞品，自动修改代码、运行测试或提交 PR 本身不能作为独创性证明。当前定位是围绕 SDK 版本升级的完整任务管理与可追溯验收。优势必须通过对照实验形成，不预先声称超过通用 Agent。

## 为什么使用 Agent

版本变化、项目封装和测试错误的组合难以完全枚举，适合由 Agent 在证据与工具反馈之间迭代。版本约束解析、权限校验、状态流转和完成判定采用确定性代码。对于稳定可描述的机械变换，优先调用规则或脚本。
