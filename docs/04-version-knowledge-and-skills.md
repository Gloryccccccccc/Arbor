# 04 版本知识检索与迁移 Skills

版本感知 RAG 是第一版的核心设计：检索适用于当前 SDK、源版本、目标版本与调用符号的迁移依据，供 Agent 分析并生成代码修改。向量召回、混合排序和重排序是否加入，需要实验决定；不能把所有版本文档混在一起后仅按语义相似度取前几条。当前尚未实现检索功能。

## 知识模型

| 对象 | 关键字段 |
| --- | --- |
| DocumentSnapshot | package、文档版本、来源 URL、抓取时间、内容哈希、来源类型 |
| MigrationChange | 适用源版本范围、目标版本范围、符号、变更类型、迁移说明、证据引用 |
| ExamplePair | 成对的迁移前后代码、适用条件、验证方式 |
| SkillManifest | 技能 ID、版本、SDK 范围、前置条件、操作步骤、验证命令与已知限制 |

## 知识来源与入库

1. 优先收集官方迁移指南、Release Notes 和版本化 API 文档；经过验证的案例另行标明来源类型与适用条件。
2. 保存原始文档快照、来源 URL、抓取时间和内容哈希，确保升级报告能引用执行时的版本。
3. 按变更条目、API 符号与章节组织切片，保留标题层级、前置说明和完整的迁移前后代码对。
4. 为变更记录 SDK、版本适用范围、涉及符号和证据引用；无法确定版本归属时标为待确认，不强行归类。
5. 新文档形成新知识包或新修订；旧任务仍能定位原有快照。检索索引可重建，原始知识不能只存在于索引中。

## 检索策略

- 先按包标识和版本适用性筛选；Python 版本约束采用符合 PEP 440 的解析能力，不以 npm semver 直接替代。
- 根据受影响的 import、方法名、异常名和配置项检索；保留标题层级与迁移前后代码对。
- 小规模知识包先建立关键词与符号检索基线。向量召回和混合排序作为对照方案，按命中率、版本误命中率、迁移成功率与成本决定是否启用。
- 输出固定快照的证据 ID 与来源，不把未找到依据的推测标为已确认变更。知识缺失时允许阻塞或请求用户提供官方资料。

从版本 A 升级到 C 时，需要检查 A→B→C 中间版本的不兼容变化，不能只检索 C 的最新说明。检索输入包括 SDK、源版本、目标版本、受影响符号和当前错误；结果包括变更内容、适用条件、迁移示例、来源及证据 ID。

首版建立关键词与符号检索基线。文档全文检索可采用 SQLite FTS5/BM25，代码标识符另做精确匹配或规范化索引，避免方法路径被普通分词破坏。具体 SQLite 驱动及构建须验证 FTS5 支持和跨平台打包兼容性。

语义召回用于弥补同义描述、概念变化等关键词漏检。候选方案为 Embedding 召回与关键词召回融合；只有在固定评估集上改善版本证据命中、迁移结果或成本时才保留。向量库和重排序器不作为 RAG 成立的前提。

## Skills 的用途

Skills 表达某类升级的可复用步骤、注意事项与验收方法。适用性由 SDK 与版本等确定性条件预筛选；稳定机械变换交给脚本。Skill 文本既不是权限控制，也不是验收结果。第一版先人工编写少量技能，再依据已验证案例维护版本。

迁移经验记录某次具体升级的条件、操作、结果与证据；Skill 提供可重复执行的步骤、前置条件与验证方法。经验经过归纳和审核后可以成为 Skill 的依据，但一次成功案例不足以证明通用适用性。Skill 维护保留案例引用与版本边界，不允许模型自动改写权限或验收策略。

## 与数据库、记忆及 MCP 的关系

| 概念 | 在本项目中的作用 |
| --- | --- |
| 数据库 | 保存文档与版本元数据、任务状态、证据和索引关联 |
| RAG | 查找适用知识，并将证据交给 Agent 分析和生成修改 |
| Memory | 保存任务中形成的事实、项目约定和经验证的迁移经验 |
| Skills | 表达可复用操作流程及其适用条件和检查方法 |
| 工具调用 / MCP | 将检索等能力接入 Agent；改变接入方式不改变检索业务逻辑 |

第一版由 Pi 的 search_migration_docs 领域工具调用检索服务。RAG 输出提供迁移依据，升级成功仍由实际执行和独立验证判定。外部知识、项目记忆和经验可以使用共同的检索基础设施，但保留不同来源、作用域与可信状态。

## 存储与扩展

首版本地维护带版本的知识包、元数据与检索索引，任务记录知识包哈希。若后续共享知识库规模和检索实验支持，再建设服务端 MySQL 元数据 + Milvus 向量索引；此时由服务端运维，终端用户无需部署。索引可以重建，不能成为唯一事实来源。

## 评估问题

至少比较无外部检索、版本过滤后的关键词检索、版本过滤后的混合检索。跨版本混淆、缺少迁移代码对和过期技能需要单独记录。
